**Goal**
Answer why the engine has two storage interfaces and define the recommended shape if they are exposed as one storage option.

**Findings**
- `adr/006-aggregation-windows.md` defines `AggregationStore` as append-window state keyed by `(ruleId, actionId, keyId)` for projected event history.
- `adr/007-temporal-absence-rules.md` defines `ScheduledStore` as deferred-check queue state keyed by `(ruleId, keyId)` with enqueue, atomic claim/lease, remove, and reschedule operations.
- `adr/007-temporal-absence-rules.md` explicitly says the interfaces are separate because the operations are too different, while one Redis/SQLite backend may implement both with separate key schemas.
- `engine/src/engine/engine.ts` uses `aggStore` only in aggregate-rule evaluation and `schedStore` only for schedule enqueueing plus scheduler tick processing.
- `engine/src/public/stores.ts` is the public contract for both stores.

**Recommended Answer**
- Keep `AggregationStore` and `ScheduledStore` as separate operational contracts.
- If a single storage option is needed, add a namespaced wrapper rather than flattening semantics:

```ts
export interface EngineStorage {
  aggregation: AggregationStore;
  scheduled: ScheduledStore;
}
```

- A backend package can implement both over one physical database while preserving separate schemas/tables/keyspaces.
- A flat interface like `interface EngineStore extends AggregationStore, ScheduledStore {}` is possible, but less clear because it mixes unrelated method families and exposes ambiguous names like `remove`/`claim` beside append-window methods.

**If Implementing Later**
- Modify `engine/src/public/stores.ts` to export `EngineStorage`.
- Modify `engine/src/public/engine.ts` to add `storage?: EngineStorage` to `EngineOptions`.
- Modify `engine/src/engine/engine.ts` constructor to resolve `aggStore` and `schedStore` from `opts.storage` while preserving existing `aggregationStore` and `scheduledStore` options unless a breaking API cleanup is desired.
- Add tests for constructor resolution and mixed options behavior.

**Verification**
- Run `npm test` from `engine/` if code changes are made.
- For explanation-only work, verify against ADR-006, ADR-007, `engine/src/public/stores.ts`, and `engine/src/engine/engine.ts`.
